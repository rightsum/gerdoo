# 018 — Hardware echo cancellation: the XVF3800 takes over mic and speaker

| | |
|---|---|
| **Date** | 2026-09-15 |
| **Type** | Hardware change + removal of software workarounds |
| **Status** | ✅ Deployed · 🔄 Barge-in and wake-word range still to re-test in real calls |
| **Severity** | Routine — but it retires the most fragile part of the voice stack |

---

## Why

Logs 014 and 015 were mostly about one problem: the robot hearing itself. The Brio
captured and a separate USB speaker played, so the two ran on **independent clocks**.
Software echo cancellation across two clocks needed a pile of compensation:

- PulseAudio `module-echo-cancel` with drift correction every second
  (`adjust_time=1 adjust_threshold=1`), without which cancellation collapsed after ~30 s
- a content filter in the agent that compared every transcript against what the robot
  had just said (`difflib` ratio or any shared 4-word run) and threw matches away
- interruption thresholds raised above LiveKit's defaults so residual echo would not
  count as barge-in
- waiting for the "janam" chime to finish, plus 0.4 s of settle, before the browser
  joined, so the chime was not transcribed as the first user turn

Barge-in worked, but rested on the filter compensating for imperfect cancellation.

The fix was always going to be hardware: one device that plays and captures on the
same clock and cancels against the exact samples it outputs.

## The hardware

**reSpeaker Flex XVF3800 Circular-4 with XIAO ESP32S3.** 4-mic circular array, XMOS
XVF3800 (AEC, beamforming, noise suppression, AGC), TPA3139D2 amplifier for a 4 Ω
speaker.

- **Power:** the board takes 5 V on USB-C / 5 V JST, or **12 V on its 2-pin terminal**.
  It is fed 12 V from the battery on the terminal; USB-C to the Jetson carries data.
  Checked against Seeed's listing before anything was changed.
- **Firmware:** Seeed's wiki says the XIAO variant ships with I2S firmware and is then
  invisible over USB. This unit was **already on the 6-channel USB firmware** — it
  enumerated straight away:

```
$ lsusb
Bus 001 Device 018: ID 2886:001e Seeed Technology Co., Ltd. reSpeaker Flex XVF3800 C16K6Ch
$ cat /proc/asound/C16K6Ch/stream0
Playback:  S16_LE  Channels: 2  Rates: 16000
Capture:   S16_LE  Channels: 6  Rates: 16000
```

The old USB speaker was already unplugged; the XVF3800 was PulseAudio's default sink
and its 6-channel input the default source.

## Which channel is which

Seeed documents the 2-channel layout (left = conference output after AEC, beamforming
and post-processing; right = ASR beam). For the 6-channel firmware, measured rather than
assumed — the chime played through the board while all six channels were recorded:

```
ch0: quiet_rms=   12.0  loud_rms=   297.4
ch1: quiet_rms=    6.2  loud_rms=   148.9
ch2: quiet_rms=    2.4  loud_rms=    29.1
ch3: quiet_rms=    2.1  loud_rms=    24.2
ch4: quiet_rms=    1.8  loud_rms=    16.7
ch5: quiet_rms=    2.4  loud_rms=    29.1
```

and 20 s of music, per second:

```
sec     ch0     ch1     ch2     ch3     ch4     ch5
  0     487     243      10      19      11      10     <- before playback
  2      15       9      10      18      11      10
 12     670     334      23      38      21      23
 16       8      15      21      27      16      21
```

- **ch0 and ch1** move together at a fixed ~2:1 ratio and are far louder than the raw
  mics — the processed outputs with AGC applied (ch0 conference, ch1 ASR beam).
- **ch2–ch5** are the four raw microphones: low, similar to each other, following the
  room.
- ch0 can swing well away from the raw mics (seconds 0 and 16), which is AGC and
  post-processing at work. **These numbers do not measure how much echo is cancelled** —
  AGC makes before/after levels on ch0 incomparable. The real test is a call.

## What changed

### Routing — `wake-word/audio-setup.sh`, rewritten

- **`gerdoo_mic`**: a `module-remap-source` taking **channel 0 only**, mono, made the
  default source. Firefox given the 6-channel source downmixes it and blends the
  un-cancelled raw mics back in.
- Default sink: the XVF3800. Everything must play through it — the hardware only
  cancels what it plays itself.
- `module-echo-cancel` is **unloaded if present**, never loaded.
- `module-stream-restore` stays unloaded (unchanged from 015).
- Devices resolved by name (`XVF3800`), never card index.

### Software workarounds removed

| Removed | Where |
|---|---|
| PulseAudio `module-echo-cancel` + drift correction | `audio-setup.sh` |
| `is_own_echo()` / `recent_agent_speech` transcript filter, `difflib` | `voice-agent/agent.py` |
| Interruption `min_duration: 0.6`, `min_words: 2` → LiveKit defaults | `voice-agent/agent.py` |
| Explicit `resume_false_interruption` / `agent_false_interruption_timeout` (added "for echo"; equal to the defaults) | `voice-agent/agent.py` |
| Wait for the chime to finish + `CHIME_SETTLE_S = 0.4` | `wake-word/wake_word.py` |

### Kept, deliberately

- **Browser `echoCancellation` / `noiseSuppression` / `autoGainControl` off.** Not a
  workaround: the hardware already did all three, and a second canceller in series
  works from an altered signal.
- **Interruption `mode: "vad"`** — "adaptive" needs LiveKit Cloud and 401s on a
  self-hosted server.
- **The wake word releases the mic during a call and when voice is off.** Through
  PulseAudio the browser could share it now, but "off" should mean closed.
- Non-speech bracket filter for Scribe tags — noise, not echo.

### Wake word

`--device-name Brio --gain 3.0` → `--device-name pulse --capture-rate 16000 --gain 1.0`.
`pulse` resolves to `gerdoo_mic`. Gain drops to 1.0 because ch0 has its own AGC; 3.0
was tuned for the Brio and would clip. Default `CAPTURE_RATE` 48000 → 16000 (the
48 k default existed for the old speaker's 48 k-only endpoint).

## "The volume is too low"

First report after the switch. PulseAudio sink at 100%, `PCM` at 80% — and still quiet.

```
$ amixer -c C16K6Ch scontents
Simple mixer control 'PCM',0     Front Left: Playback 60 [100%] [0.00dB]
Simple mixer control 'PCM',1     Mono: Playback 40 [67%] [-20.00dB]
```

**Root cause:** the card has **two** playback controls. `amixer sset PCM` only touches
`PCM,0`; `PCM,1` is a mono master that ships at **-20 dB** and caps everything above
it. Setting it to 0 dB is +20 dB.

**Fix:** `audio-setup.sh` sets both `PCM,0` and `PCM,1` to 100% on every run.

## Verification

- `pactl list short modules | grep -c echo-cancel` → `0`
- Default source `gerdoo_mic` (`s16le 1ch 16000Hz`), default sink the XVF3800
- `wake-word` and `robot-face` restarted; detector logs `gain=1.0` and honours the voice
  switch
- LiveKit server and agent restarted; agent registered
- voice-agent test suite: 57 passed
- Both `PCM` controls at 0 dB after re-running `audio-setup.sh`

**Not yet verified:** barge-in without the software filter, whether the robot ever
hears itself, whether the chime leaks into the first turn, and wake-word range at
gain 1.0. Those need real calls.

## Takeaways

- **Fix echo where the clock is.** Every software layer in 014–015 was compensating for
  capture and playback living on different clocks. One device removed all of them.
- **A multichannel mic array is not a mic.** Hand the processed channel to applications
  explicitly; a downmix silently reintroduces what the DSP removed.
- **`amixer sset <name>` only sets index 0.** List `scontents` and look for a second
  control with the same name before calling hardware quiet.
